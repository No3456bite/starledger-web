# 历史账单猜测

## 参考

- [beancount-import](https://github.com/jbms/beancount-import) 从用户确认的历史分录训练决策树，预测待导入交易的账户，并允许用户在入账前更正。这说明“历史学习 + 人工确认”适合财务数据，但其 Python 导入管线不适合直接放进此纯静态网页。
- [Actual Budget](https://github.com/actualbudget/actual) 提供自动分类的规则思路。确定性的商家/金额规则适合高置信度情况，但不足以给无商家截图按金额分布提供候选。

## 本项目的最小实现

`history-predictor.js` 只读当前主账本的历史记录，不上传交易。先筛掉不同收支类型、币种、删除记录和正在编辑的账单，再按商家文字相似、金额比例、备注、账户、时间段及历史频次排序。分数只用于排序，不是统计学概率。

记一笔展示最多三个“历史猜测”，点击后才采用大类/小类。OCR 原有的明确文本识别和精确金额匹配保持优先；只有商家相似、有多笔一致历史支持且领先其他分类时，相似度结果才自动预填。没有商家时，金额大小可以影响候选顺序，但不能单独触发“高”置信度或自动分类。

此方法不会推断新类别、不会复制历史备注，也不能保证只有金额时的分类正确。用户保存前始终可以修改。
